What changed.
What the results mean.

V1 and v2 use GPT-5.4 mini. V3, v4, and v5 use GPT-5 mini. V5 compares reactive and quota-aware policies on the same five deployments, with 520 records per arm and explicit average request timings.

Same model is not the same test. Same prompt is not the same capacity.

V1 → v2 changed prompt complexity, record count, output ceiling, and allocation. V2 → v3 kept the prompt but changed the model, allocation, pacing, count, and grouping. Do not attribute the differences to the GPT model alone.

Within v4, both arms hold model, prompt, records, five workers, retry logic, and total quota constant. This is a new cloud pilot, not a resumption or completed baseline for interrupted v3.

Then, separate speed from correctness

Measured outcomes

These columns are not a leaderboard.

V1 timings cover 100 compact records; v2 covers 13 complex records; v3 targets 1,700 and retains its explicit evidence state; v4 covers 65 per arm; v5 covers 520 per arm on a fresh matched pool. Faster elapsed time on a smaller workload does not establish a faster model.

Averages are measured, not inferred. Missing historical means say “Not recorded.” A p50 is not a mean, and job time divided by record count is throughput-related, not average request latency. V5 reports successful HTTP, successful/all record processing, and backlog-inclusive completion separately.
