The hypothesis, not a promise.

Separately allocated deployments may behave differently under load. This pilot tests that hypothesis without increasing aggregate quota in the pool arm. It does not expose backend scale-up state, prove that all 429s have one cause, or guarantee a threefold speedup.

One deliberate retry layer

Maximum four total attempts per record across all targets, not four retries per deployment. The router respects service retry headers for the affected target; fallback is 30-second exponential backoff plus bounded jitter. Healthy targets remain eligible.

This observation profile has no proactive token-rate pacer. It measures throttling and cooldown behavior rather than promising to prevent every 429.

Durable, not service Batch

Azure Durable Functions runs both arms using Durable Task Scheduler. Timers release workers while waiting. Private Blob intents and responses prevent blind replay of uncertain paid calls.

No Azure Batch jobs, Batch discount, PTUs, quota increase, new subscription, or cross-region deployment were used.
